# Index-Translate-2B 全版本与后端全量对比

更新：2026-10-22。包含 GGUF 量化、Transformers/vLLM 后端对照，以及约 6.5 GiB 整卡显存预算下的全量复测。

## 部署选择

| 使用条件 | 推荐方案 | 本次依据 |
|---|---|---|
| RTX 3090、约 6.5 GiB 显存预算、批量翻译 | **FP8 + vLLM** | 6.55 GiB、77.35 句/秒，约为同预算 Q8_0 的 3.75 倍；质量总体接近，COMET 有小幅下降 |
| 更重视原精度，且能留出较多缓存空间 | **BF16 + vLLM** | 原配置约 21.6 GiB 时 78.12 句/秒；同预算 6.48 GiB 时降为 53.19 句/秒 |
| 确定使用 Transformers | **原版 BF16** | 本环境中 19.74 句/秒、整卡约 10.55 GiB，比软件 QDQ 的 FP8、NVFP4 快 |
| 确定使用 GGUF / llama.cpp | **Q8_0** | 质量接近 F16，权重约 2.08 GB；新一轮完整采样为 6.54 GiB、20.62 句/秒 |

同预算复测后，当前批量部署首选由“BF16 + vLLM”调整为“FP8 + vLLM”。该选择针对本次 RTX 3090、128 并发、FLORES 中文翻八语的配置；尚未测单请求延迟。NVFP4 在同预算下为 76.48 句/秒，略低于 FP8，三个神经质量指标相对 Q8_0 的配对区间均显示退化，因此当前不优先采用。

FP8 的质量不能写成与 Q8_0 完全相同：同预算下 COMET 差值为 −0.000437，95% 区间 [−0.000752, −0.000141]；MetricX、XCOMET 的差值区间覆盖 0。FP8 在 RTX 3090 上实际使用 Marlin W8A16，NVFP4 使用 W4A16；执行路径以本次日志为准，参见 [vLLM FP8 支持说明](https://github.com/vllm-project/vllm/blob/main/docs/features/quantization/llm_compressor/fp8.md)。

## 数据与指标口径

FLORES-101 devtest 中文→英语、法语、德语、西班牙语、俄语、日语、韩语、阿拉伯语；每系统每语种 1,012 条。同一 GPU1（RTX 3090 24 GiB），greedy 解码、禁用 thinking、最多生成 512 token。所有评分覆盖全量输出。

- **BLEU（spBLEU、BLEU-13a）**：衡量与参考译文的 1–4 gram 片段匹配。`BLEU = 100 × BP × exp((1/4)Σ log pₙ)`，`pₙ` 是截断 n-gram 精确率，`BP = min(1, exp(1−参考长度/译文长度))`。spBLEU 用 `flores200` SentencePiece；13a 用 `13a` tokenizer，只报告英、法、德、西、俄、阿六语。
- **chrF++**：衡量字符和词片段匹配，使用字符 1–6 gram、词 1–2 gram 的精确率 P 与召回率 R，`Fβ = (1+β²)PR/(β²P+R)`，β=2，偏重召回。
- **COMET WMT22-DA**：将源文、译文、参考译文送入评分模型，预测人工质量评价；越高越好。
- **MetricX-24 Hybrid XL**：本次使用 reference-based 模式，将源文、译文、参考译文送入评分模型，预测错误分；越低越好。
- **XCOMET-XL**：预测句级整体质量并定位错误跨度；表中列整体质量分，越高越好；实验 A、B 保存错误跨度，实验 C 的新增 XCOMET 评分只保存句分。
- **均值**：BLEU、chrF++ 先对各语种的完整语料计算，再做语种等权平均；三个神经指标先对各语种 1,012 句分求均值，再做语种等权平均。BLEU-13a 平均六语，其余平均八语。质量分不是准确率百分比。
- **速度**：句吞吐 = 全量句数 / 生成 wall time；token 吞吐 = 全部生成 token / 同一时间。服务加载、启动编译和指标评分不计入翻译速度；显式预热若执行则排除。实验 C 的 vLLM 有 128 次预热，Q8_0 未额外执行客户端预热，其正式计时包含服务启动后的首批请求。各语种速度采用各自的 wall time，不相加；跨语种并发使其与全量吞吐的统计区间不同。单轮测速未计算速度置信区间。

## 实验 A：早期 BF16 Transformers 与 GGUF 量化

### 结论与范围

比较 BF16 Transformers、官方 F16 GGUF（llama.cpp）、Q8_0、Q6_K、Q4_K_M 五种部署。数据为 FLORES-101 devtest 中文→英语、法语、德语、西班牙语、俄语、日语、韩语、阿拉伯语；每版 8,096 条、每语种 1,012 条，合计 40,480 条译文。

Q8_0 与 F16 GGUF 的宏平均十分接近。COMET、MetricX、XCOMET 的配对 bootstrap 95% 区间均覆盖 0；这表示本次数据下未检出这些宏平均差异偏离 0 的证据，不证明两版等效。Q4_K_M 本次句子和 token 吞吐最高，主要质量均值比 F16 稍低。不要把这些单一数据集结果当作普遍结论。

F16 GGUF 全量翻译和五类指标评测均已完成。HF 与 F16 的最终提示文本及 token ID 在 `id=1` 的八种目标语言抽样中 8/8 一致；这只是 8 组抽样检查。Q6_K 俄语 `id=327` 输出重复至 512-token 上限，保留在计分中。

- 同一 FLORES-101 devtest 源数据、参考译文、翻译任务提示；均为 greedy 解码，最大生成 512 tokens、禁用 thinking。BF16 Transformers 使用 `do_sample=False`、batch 128；GGUF 使用 temperature=0、top_p=1，由 llama.cpp CUDA 服务处理，客户端并发 128，服务端 batch 8192、ubatch 2048、总 context 131,072，提示缓存关闭。速度不含模型加载及指标评分。
- 五版均使用 GPU1（NVIDIA RTX 3090 24 GiB）。HF 基线来自 `IndexTeam/Index-Translate-2B` 的本机原始 safetensors；官方 F16 GGUF 固定在 revision `3a0eca6ce931d88d00614d427ab3ed8ff0743902`，SHA-256 `f9ab1279d1169ad18655a7b8085a9111bef12a0e2eb733aaa2234186241e5ad7`。

## 实验 B：BF16、FP8、NVFP4 的 vLLM 与 Transformers

每种后端覆盖 FLORES-101 devtest 的 8,096 条中文源句到八种目标语言翻译，每语种 1,012 条。BLEU、chrF++、COMET、MetricX、XCOMET 均使用本目录中的新鲜评分结果。三个神经指标先按 `(source, hypothesis, reference, language)` 精确去重，再将分数映射回全部系统输出。
本次对照共映射 48,576 个系统输出，神经模型只需评分 25,896 个不同输入；覆盖检查通过。

运行设置：vLLM FP8 / NVFP4 是 W8A16 / W4A16；Transformers FP8 / NVFP4 是 W8A8 / W4A4，使用 BF16 计算并解压权重后通过 compressed-tensors 软件 QDQ 执行。两种后端的量化路径不同。Transformers 日志记录 `fast_linear_attention_available=False`，Qwen3.5 fast linear attention 依赖未安装，因而回退至 PyTorch 实现；速度只代表本次环境。速度来自生成阶段记录，指标评分耗时不计入翻译吞吐。

### 运行口径

- Q8_0 和 vLLM 共用同一 FLORES-101 devtest、提示词、贪心解码及 512 token 上限。Q8_0 使用 llama.cpp；vLLM 根据上一轮整卡峰值校准 `gpu_memory_utilization`，再按请求区间遥测反馈调整。
- BF16 的低显存运行与原高显存运行逐条译文一致率见表；FP8/NVFP4 也列出与原运行的一致率。所有译文变化都进入本轮质量统计。
- RTX 3090 上 FP8 和 NVFP4 使用 Marlin W8A16/W4A16，而不是原生 FP8/FP4 激活计算。每种版本实际显存峰值在 6.48–6.56 GiB。
- 显存为 `nvidia-smi` 整卡采样，Q8_0 379 个样本；BF16、FP8、NVFP4 vLLM 分别为 147、101、102 个样本。单轮吞吐不含服务加载与指标评分；vLLM 排除 128 次预热，Q8_0 首批请求包含在正式计时中。token/s 使用全量生成 token 数除以推理 wall time。
- XCOMET 对 15,770 个与此前版本完全相同的输入复用了同 checkpoint 分数；对剩余 2,583 个唯一输入新评分。COMET 和 MetricX 对全部 18,353 个唯一输入新鲜评分。
