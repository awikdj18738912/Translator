# 中文转录 → 中文精修 → 外语翻译

2026-10-20，按用户要求切换当前生产工作台的方向。网页地址为 http://127.0.0.1:8083/，ASR 为8766。只手动重载网页服务一次；ASR进程保持运行。两个持久systemd用户单元均为 `Restart=no`。

## 实现

- Qwen3-ASR-0.6B固定识别中文，目标语言选择不再影响ASR语言参数。
- 中文文本先进入现有三标点块精修窗口，保留v90数字规则、实体保护、正则门控及精修输出校验；不使用ASR置信度。
- 只有已完成精修、规则检查后的中文前缀进入LMT-60-0.6B。待精修ASR尾部可以显示，但不会提前翻译。
- 每完成一组精修即交接翻译，ASR和精修各自可继续运行。两个边界各仅保留一份待处理最新快照，避免长音频积压无界队列。
- 翻译使用明确的Chinese→目标语言官方提示模板，支持英、法、德、西、俄、日、韩、阿八种目标。保留CT2 int8_float16；先真实token预览，再beam 3确认并缓存。
- 页面三列顺序为“中文转录 / 中文精修 / 外语翻译”，保留五项统计和术语库。中文与翻译使用独立修订号，翻译事件不会把较新的中文列覆盖回旧版本。

入口为 `workbench/app.py`，新调度为 `workbench/system/chinese_translation_pipeline.py`。通用翻译路由默认值和早期 `translator/` 基础原型保留兼容；当前部署显式使用 `pipeline_direction=zh_to_foreign`。

`PYTHONPATH=workbench python -m pytest workbench/tests -q`：**175 passed, 1 skipped**，见 `tests.log`。跳过项是系统测试解释器缺少PyAV；生产解释器实际音频上传、解码、ASR和后续链路已验证。新增覆盖中文精修先于翻译、未精修尾部隔离、中文ASR语言固定、ASR不等待阻塞精修、目标语言校验、翻译异常恢复及取消期间模型锁持有。

`frontend_offline.json` 是模拟事件浏览器验证。`browser_live.json` 是真实GPU服务的9次页面验证：八种目标语言各一个文本样例，加一次12秒中文音频→英语。检查每次翻译输入来自已经发布的中文精修前缀，最终输入等于最终精修中文；检查token预览、三列内容、五项统计、桌面/手机布局。没有浏览器错误。各次完整事件见对应 `*_events.json`，截图为 `text_english_desktop.png`、`audio_desktop.png` 和 `audio_mobile.png`。

英文外贸样例：

> 输入：嗯，我们需要三百个不锈钢阀门。单价是十二点五美元。请在星期五之前发货。
>
> 精修中文：我们需要300个不锈钢阀门。单价是12.5美元。请在星期五之前发货。
>
> 外语翻译：We need 300 stainless steel valves. The unit price is $12.5. Please ship before Friday.

该例精修请求2次、门控跳过1组；一次精修输出未通过数字守卫，保留规则处理后的安全中文并继续翻译。成功显示译文不意味着每次精修生成都被接受。

## 已知限制

这些是小样本功能验证，没有参考译文打分、多人听写或准确率统计。俄语等输出仍有语法问题，不据此宣称各语言质量达标。

中文音频的正确ASR结果经过数字规则后为：`今天是2015年12月5日，我有37%的概率获得123万7851元。` 下游MT输出为：`Today is December 5, 2015. I have a 37% probability of winning 1230,007851 yuan.` 金额错译发生在翻译模型；中文数字规则没有错改数值。当前数字锁定保护的是中文精修，尚无外语数字校验或纠错。本轮没有引入Python数字兜底，不能把“中文数字规则正常”当作“外语数字可靠”。

分组精修和确认带来等待，token预览仍可能修订；这不是原生跨音频状态的同声传译模型。保留50MiB文件限制，取消时已运行的GPU调用需退出后才释放模型占用。
