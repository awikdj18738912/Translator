# Qwen3-ASR-0.6B 流式显存缩减实测

2026-10-22，GPU0 / RTX 3090，BF16、vLLM 0.14.0。已部署 **4096 上下文 + 512 MiB KV + 1024 prefill + CUDA graph**。

| 配置 | KV MiB | ASR 进程采样峰值 MiB | 240秒音频HTTP耗时中位数 | 最终文本逐字一致 | 最长提示检查 |
| --- | ---: | ---: | ---: | --- | --- |
| 原配置：8192 / CUDA graph | 1024 | 3818 | 11.48 秒 | 15/15 | 通过 |
| 采用：4096 / CUDA graph | 512 | 3606 | 11.63 秒 | 15/15 | 通过 |
| 2048 / CUDA graph | 256 | 3168 | 12.50 秒 | 12/15 | 2092 tokens 超过 2048 上限 |
| 4096 / eager | 512 | 3564 | 42.88 秒 | 12/15 | 通过 |

## 判断

- 4096 档相对原配置，ASR 进程峰值从3818降至3606 MiB，节省212 MiB（5.6%）；速度中位数变化约+1.3%，本轮不足以声称统计等价。15次最终文本完全一致。
- 2048档峰值3168 MiB，节省650 MiB（17.0%）；循环长音频出现一处句号变逗号，最长提示请求失败，因此未作为兼容现有接口的默认配置。
- eager档峰值3564 MiB，只比4096 CUDA graph省42 MiB，240秒处理耗时约3.69倍，流式使用不值得。此前观测到的约2941 MiB是较早阶段采样，不是完整测试峰值。
- 4096档启动后2598 MiB，预热阶段峰值2960 MiB，后续压力测试升至3606 MiB；不能用刚启动数字替代运行后占用。

## 测试口径

- 五个样例各完整重复3次：5.97秒英语、12秒中文、40.848秒真实中文、真实中文循环至240秒、人工拼接60秒密集语音。每档15次，共60次；另有预热和最长提示容量检查。
- 2秒PCM块顺序推送，不按真实时间sleep；HTTP耗时为start/chunk/finish请求合计，不含音频解码，不代表实时首字延迟或整套翻译延迟。表中耗时取三次中位数。
- 保留VAD及30秒软分段/45秒强制分段。官方流式实现每次重新传入当前段累计音频及已识别前缀；流式并不代表每次只有最新的一小块。
- 峰值：NVML每200毫秒采样，仅统计ASR服务MainPID后代在GPU0的显存，覆盖预热、请求和容量检查，不包含引擎启动瞬时峰值；整卡读数还包括CUDA/显示驱动和可能的其他分配。
- 文本一致率为对应样例与原配置逐字比较，含标点；没有人工参考听写，不能当作CER/WER准确率。最长提示为2048字人工容量压力输入，不用于识别质量结论。
- 五个音频仍属小样本，循环音频和密集拼接不是自然长录音。没有权重量化或降低BF16精度。
- 首次原配置warmup遭遇磁盘I/O等待，已单列且不参与速度统计。首次4096重启被旧EngineCore停机阻塞，记录在compact_4096_startup_timeout.json；补跑已成功，未把该失败算为容量不足。

## 文件与部署

- 原始证据：同目录四个配置JSON（逐块文本、延迟、NVML采样、启动日志），fixtures.json记录音频散列；comparison.json为汇总。
- 可复现脚本：项目根目录 scripts/benchmark_asr_memory.py。脚本会暂时切换ASR用户服务配置；实验覆盖需要在选定配置后清理。
- 默认参数已写入 workbench/start_asr.sh；临时90/91实验drop-in已清理。当前进程已使用4096/512MiB/1024，健康接口确认audio_ready=true。9项ASR启动参数测试通过。
